# 알려진 한계 (2026-10-27 기준)

| # | 한계 | 영향 | 대응 / 상태 |
|---|---|---|---|
| L1 | Orca가 Claude **세션 ID를 노출하지 않음** | 같은 worktree에 Claude가 둘 이상이면 자동 매칭 불가 | 매번 수동 선택(실 Orca E2E에서 확인). JARVIS가 만든 세션의 UUID는 기록만 함 |
| L2 | `tui-idle`이 대화상자 표시 중에도 충족됨 | 준비 상태 오판 가능 | 화면 텍스트로 대화상자를 판정(ADR-6). Claude Code 2.1.311 문구 기준 휴리스틱이라 버전이 바뀌면 다시 채취 필요 |
| L3 | 새 Claude 세션 기동 시 MCP 승인 대화상자가 뜰 수 있음 | 새 프로젝트 흐름이 `Claude 플랜 모드 확인` 단계에서 멈춤 | 자동 응답하지 않음. Orca에서 처리한 뒤 '이어하기'. 실제 Orca에서 '이어하기'를 실행해 본 적은 없음(단위 테스트만 있음) |
| L4 | Git 저장소 안 폴더를 `repo add`하면 상위 저장소로 해석됨 | 기본 상위 폴더가 Git 저장소 안이면 새 프로젝트가 상위 worktree에 묶임 | 기본 상위 폴더는 Git 밖에 두기를 권장. **Git 밖 빈 폴더의 `kind: folder` 등록은 미검증**(테스트 폴더를 프로젝트 밖에 만들 수 없음) |
| L5 | ad-hoc 서명 | 재빌드하면 마이크 권한을 다시 물을 수 있음 | 개인 로컬 실행 전제. 공증 없음 |
| L6 | Xcode 없음 → `swift test` 미동작 | 테스트 실행 방식이 표준과 다름 | `swift run JARVISCoreTestRunner` |
| L7 | 원격 호스트(ssh·paired server) | 전송 대상에서 제외 | 목록에 미확인/원격으로 표시 |
| L8 | 스킬 목록은 파일 스캔 + Orca 목록 기준 | 내장·계정 동기화 스킬은 빠질 수 있음. 플러그인 호출명은 추정 | "전체 목록 아님"을 표시하고, 추정 스킬은 사용자 확인 후에만 전송 |
| L9 | 로컬 LLM 미설치 | 분류는 규칙만, 메타 프롬프트는 템플릿만 | 모델 다운로드 승인 대기(`docs/model-download-plan.md`). LLM 기반 AC-05·06·11·24 측정 미수행 |
| L10 | 패널 높이는 단계별 고정값 | 내용이 많으면 내부 스크롤 | PRD의 '내용에 따른 높이'는 부분 구현 |
| L11 | 검증 환경에서 `screencapture` 불가(화면 기록 권한 없음) | 스크린샷 증거 없음 | 접근성 트리·진단 로그로 대체 |
| L12 | 일부 아이콘 버튼의 접근성 이름이 비어 있음(접근성 트리에서 이름 없는 `button`) | VoiceOver 사용성 저하 | 개선 필요 |
