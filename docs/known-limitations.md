# 알려진 한계 (2026-10-27 기준)

| # | 한계 | 영향 | 대응 / 상태 |
|---|---|---|---|
| L1 | Orca가 Claude **세션 ID를 노출하지 않음** | 같은 worktree에 Claude가 둘 이상이면 자동 매칭 불가 | 매번 수동 선택(실 Orca E2E에서 확인). JARVIS가 만든 세션의 UUID는 기록만 함 |
| L2 | `tui-idle`이 대화상자 표시 중에도 충족됨 | 준비 상태 오판 가능 | 화면 텍스트로 대화상자를 판정(ADR-6). Claude Code 2.1.311 문구 기준 휴리스틱이라 버전이 바뀌면 다시 채취 필요 |
| L3 | 새 폴더에서 Claude를 띄우면 폴더 신뢰·MCP 승인 대화상자가 뜸 | 새 프로젝트 흐름이 매번 한 번은 멈춤(실측) | 자동 응답하지 않음. Orca에서 처리한 뒤 이어하기. 실 Orca에서 이어하기 완료 확인 |
| L4 | Orca 1.4.242 CLI는 Git이 아닌 폴더를 등록하지 못함 | 새 프로젝트마다 Git 초기화 승인 또는 Orca UI에서 폴더 열기가 필요 | 'Git 초기화 후 등록(승인)' 버튼과 수동 등록 재사용을 구현했고 실기에서 확인함. Git 저장소 안의 폴더는 상위 저장소로 등록됨 |
| L5 | ad-hoc 서명 | 재빌드하면 마이크 권한을 다시 물을 수 있음 | 개인 로컬 실행 전제. 공증 없음 |
| L6 | Xcode 없음 → `swift test` 미동작 | 테스트 실행 방식이 표준과 다름 | `swift run JARVISCoreTestRunner` |
| L7 | 원격 호스트(ssh·paired server) | 전송 대상에서 제외 | 목록에 미확인/원격으로 표시 |
| L8 | 스킬 목록은 파일 스캔 + Orca 목록 기준 | 내장·계정 동기화 스킬은 빠질 수 있음. 플러그인 호출명은 추정 | "전체 목록 아님"을 표시하고, 추정 스킬은 사용자 확인 후에만 전송 |
| L9 | 소형 LLM 추천은 보수적 | 명백 요청 20개 중 6개를 수동 선택으로 미룸(오답 0) | 추천만으로 보내지 않으므로 안전. 프로젝트 설명(note)을 잘 적으면 개선 여지 있음 |
| L10 | 패널 높이는 단계별 고정값 | 내용이 많으면 내부 스크롤 | PRD의 '내용에 따른 높이'는 부분 구현 |
| L11 | 검증 환경에서 `screencapture` 불가(화면 기록 권한 없음) | 스크린샷 증거 없음 | 접근성 트리·진단 로그로 대체 |
| L12 | 아이콘 버튼 접근성 이름 | 처음 빌드에서 이름 없는 `button`으로 노출 | 설정·닫기·받아쓰기 버튼에 이름을 추가함. 접근성 트리 재확인은 M6 |
| L13 | 받아쓰기 정리는 외부 전송 | `claude -p`(Haiku 5.5)로 정리하므로 받아쓴 말이 Anthropic으로 전송되고, Claude Code 로그인이 필요하다. 정리에 4~19초 걸린다(실측: 짧은 문장 4~7초, 589자 19초) | 오프라인이면 실패하고 받아쓴 원문을 그대로 둔다. 설정에서 로컬 모델로 바꿀 수 있지만 품질이 낮다 |
| L14 | 프롬프트 기록 범위 | 훅이 설치된 Claude Code에 들어간 프롬프트만 기록. 다른 도구(Codex 등)·웹 채팅은 기록하지 않음 | 훅 경로가 `build/` 폴더에 묶여 있어 프로젝트 폴더를 옮기면 다시 설치해야 함 |
| L15 | 받아쓴 원문 짝짓기 | 런처 전송과 훅 기록을 같은 글·5분 이내로 짝지음. Claude Code가 글을 바꿔 받거나 5분 넘게 늦으면 원문이 붙지 않음 | 보낸 정리본 끝에는 원문이 이미 들어 있어 내용 손실은 없음 |
