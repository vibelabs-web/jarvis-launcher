Orca / Claude Code CLI 계약서 (Spike 0 실증)

  • 실증일: 2026-10-27 · Orca CLI 1.4.242 · Claude Code 2.1.311 · macOS 26.5.2 (M1 Pro)
  • 근거 원문: qa/evidence/spike0/ (개인 경로·제목·기기명 마스킹)
  • 명령·옵션의 근거는 orca --help(01)와 orca agent-context --json(03)뿐이다. 이 버전에서는 하위 명령 --help가 동작하지 않는다(02, Unknown command).
  • JARVIS는 아래에 검증됨으로 표시된 명령만 호출한다. 버전이 바뀌면 이 문서를 다시 실증한다.

1. 공통 규칙

  • 실행: Process에 실행 파일 URL과 인자 배열을 넘긴다. 셸 문자열 보간은 하지 않는다. 항상 --json을 붙인다.
  • 응답 봉투: { id, ok, result, _meta{runtimeId} }. ok != true이거나 종료 코드가 0이 아니면 실패로 본다.
  • Orca 실행 파일 탐색 순서: 설정값 → /Applications/Orca.app/Contents/Resources/bin/orca → PATH.

식별 가능성 (PRD 9.3-1)

  • 경로·호스트·에이전트 종류: 식별 가능. worktreePath, executionHostId, agentIdentity(claude 또는 null)를 쓴다.
  • Claude 세션 ID: 제공되지 않는다. 같은 worktree에 Claude가 두 개 이상이면 자동으로 매칭하지 않고 매번 수동으로 선택하게 한다.
  • worktreePath는 worktree 루트다. 그 하위 폴더에서 cd로 시작한 세션도 루트 경로로 보고된다(m0b-09).
  • orphaned: true이고 agentIdentity: null인 터미널은 일반 셸이거나 미확인이므로 전송 대상에서 뺀다.
  • 원격 호스트는 hostScope.omittedHostIds에 나온다. MVP에서는 executionHostId == "local"인 터미널에만 보낸다.

3. 쓰기 명령 (실증 결과)

3.1 텍스트 전송 — 검증됨 (테스트 전용 터미널, m0b-07)

orca terminal send --terminal <h> --text <text> --enter --wait-submit <s> --json

result.send.accepted: true
result.send.prompt.requestId: <uuid>
result.send.prompt.stages: ["input_accepted", "turn_started"]
result.send.prompt.provider: "claude", observation: "supported"
result.send.prompt.processIncarnation: <incarnationId와 같음>
result.mutation.replayed: false

JARVIS의 결과 매핑:

  • stages에 turn_started가 있으면 전송 확인(터미널에 전달됨)
  • input_accepted만 있으면 상태 불명
  • accepted:false이거나 ok:false이면 실패
  • 자동 재전송은 하지 않는다. 사용자가 수동으로 재시도할 때만 --retry-request <requestId>로 같은 요청을 재개한다(같은 payload와 incarnation에 묶여 있음).
  • processIncarnation이 확인 화면의 incarnationId와 다르면 이상 징후로 기록한다.

3.2 터미널 생성 — 검증됨 (m0b-02)

orca terminal create --worktree path:<worktree-root> --title <t> --command <text> --json → result.terminal.{handle, incarnationId, worktreeId, executionHostId, processId, surface}. --command 문자열은 로그인 셸에 그대로 입력된다. 따라서 경로는 작은따옴표로 이스케이프한다(' → '\'').

3.3 터미널 닫기 — 검증됨 (m0b-10)

orca terminal close --terminal <h> --tab --json → ptyKilled:false가 즉시 반환된다. 닫기는 비동기이므로 terminal wait --for exit로 exitCause.kind == operator_close를 확인해야 한다.

3.4 폴더 등록 — 부분 검증

orca repo add --path <dir> --json

  • Git 저장소 하위 폴더를 넣으면 새로 등록하지 않고 상위 Git 저장소 레코드를 반환한다(m0b-01). 이 경우 새 worktree가 생기지 않는다.
  • Git이 아닌 빈 폴더가 kind: folder로 등록되는지는 미검증이다. 기존 repo 목록에 kind: folder가 1건 있어 지원은 하는 것으로 보인다. M4에서 Git 밖의 테스트 상위 폴더로 실증한다.
  • 정리: orca project setup-delete --setup <id>로 "repo-backed setup은 repo 호환 레코드를 제거"한다(스키마 노트). 열린 터미널이 있으면 거부되고, --force로 강제할 수 있다.

3.5 사용하지 않는 명령

  • orca agent launch: Chat UI 설정에 따라 구조화 채팅으로 열릴 수 있다(스키마 노트). PRD는 TUI를 요구하므로 쓰지 않는다.
  • orca computer *(UI 자동화): PRD 5.5 절대 규칙에 따라 쓰지 않는다.

4. Claude Code 기동 계약 (G1) — 검증됨

  • 플래그(05-claude-help): --permission-mode plan, --session-id <uuid>, -n/--name <name>
  • JARVIS가 쓰는 기동 명령: cd -- '<dir>' && claude --permission-mode plan --session-id <uuid> -n <slug>
  • 플랜 모드 확인: terminal read --screen의 tail에 plan mode on이 있는 줄(m0b-06: ⏸ plan mode on (shift+tab to cycle))
  • 입력 가능 상태: 화면에 ❯ 프롬프트 줄이 있고, 아래 차단 패턴이 없어야 한다.

4.1 중요: tui-idle은 입력 가능 상태를 뜻하지 않는다 (m0b-03, m0b-04)

기동 직후 Claude가 "3 new MCP servers found in this project … Enable selected / Esc to reject all" 대화상자를 띄운 상태에서도 terminal wait --for tui-idle이 satisfied: true를 반환했다.

  • JARVIS는 대화상자(MCP 승인, 폴더 신뢰, 권한 요청, 질문)에 자동으로 응답하지 않는다. 대화상자가 보이면 사용자 확인 필요 상태로 멈추고 Orca에서 열기 / 다시 확인을 안내한다.
  • 차단 패턴(휴리스틱, 버전 의존): Enable selected, Esc to reject, Do you trust, Yes, proceed, Do you want to, ❯ 1.. 판정이 애매하면 차단한다.
  • M0b 테스트 터미널에서는 이 대화상자를 Esc(모두 거부)로 닫고 진행했다(m0b-05). 활성화한 MCP는 없다.

5. 버전 의존 위험

  • 화면 패턴(plan mode on, 대화상자 문구)은 Claude Code 2.1.311 기준이다. 업데이트되면 회귀 테스트(Tests/…/ScreenClassifierTests) 픽스처를 다시 채취한다.
  • 하위 명령 --help가 동작하지 않으므로 버전이 바뀌면 agent-context --json을 다시 채취해 비교한다.
