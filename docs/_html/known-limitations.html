#한계영향대응 / 상태
L1Orca가 Claude 세션 ID를 노출하지 않음같은 worktree에 Claude가 둘 이상이면 자동 매칭 불가매번 수동 선택(실 Orca E2E에서 확인). JARVIS가 만든 세션의 UUID는 기록만 함
L2tui-idle이 대화상자 표시 중에도 충족됨준비 상태 오판 가능화면 텍스트로 대화상자를 판정(ADR-6). Claude Code 2.1.311 문구 기준 휴리스틱이라 버전이 바뀌면 다시 채취 필요
L3새 Claude 세션 기동 시 MCP 승인 대화상자가 뜰 수 있음새 프로젝트 흐름이 Claude 플랜 모드 확인 단계에서 멈춤자동 응답하지 않음. Orca에서 처리한 뒤 '이어하기'. 실제 Orca에서 '이어하기'를 실행해 본 적은 없음(단위 테스트만 있음)
L4Git 저장소 안 폴더를 repo add하면 상위 저장소로 해석됨기본 상위 폴더가 Git 저장소 안이면 새 프로젝트가 상위 worktree에 묶임기본 상위 폴더는 Git 밖에 두기를 권장. Git 밖 빈 폴더의 kind: folder 등록은 미검증(테스트 폴더를 프로젝트 밖에 만들 수 없음)
L5ad-hoc 서명재빌드하면 마이크 권한을 다시 물을 수 있음개인 로컬 실행 전제. 공증 없음
L6Xcode 없음 → swift test 미동작테스트 실행 방식이 표준과 다름swift run JARVISCoreTestRunner
L7원격 호스트(ssh·paired server)전송 대상에서 제외목록에 미확인/원격으로 표시
L8스킬 목록은 파일 스캔 + Orca 목록 기준내장·계정 동기화 스킬은 빠질 수 있음. 플러그인 호출명은 추정"전체 목록 아님"을 표시하고, 추정 스킬은 사용자 확인 후에만 전송
L9로컬 LLM 미설치분류는 규칙만, 메타 프롬프트는 템플릿만모델 다운로드 승인 대기(docs/model-download-plan.md). LLM 기반 AC-05·06·11·24 측정 미수행
L10패널 높이는 단계별 고정값내용이 많으면 내부 스크롤PRD의 '내용에 따른 높이'는 부분 구현
L11검증 환경에서 screencapture 불가(화면 기록 권한 없음)스크린샷 증거 없음접근성 트리·진단 로그로 대체
L12일부 아이콘 버튼의 접근성 이름이 비어 있음(접근성 트리에서 이름 없는 button)VoiceOver 사용성 저하개선 필요
