JARVIS Launcher — 구현 계획 (docs/02-plan.md 초안)

상태: 작가님 승인 완료 (2026-10-27). Spike 0 원문은 docs/orca-cli-contract.md, qa/evidence/spike0/ 참조.

Context

작가님은 Orca에서 Claude Code 세션 여러 개를 동시에 운영한다. 요청 하나를 보내려 해도 매번 해당 터미널을 찾아 길게 입력해야 한다. JARVIS Launcher는 메뉴바에 상주하는 macOS 앱이다. 핫키를 누르면 가운데 패널이 뜨고, 텍스트나 로컬 받아쓰기로 입력한 내용을 앱이 추천한 Orca 세션으로 작가님 확인 후 1회 보낸다. 새 프로젝트라면 메타 프롬프트를 만들고 폴더를 만든 뒤, 새 Orca 터미널에서 Claude Code를 플랜 모드로 시작한다. 범위의 기준은 docs/01-prd.md(승인 완료)이고, 의도는 docs/00-intent.md다.

2. 결정 기록 (ADR, 작가님 확인 완료)

  • ADR-1 STT: 이미 설치된 whisper.cpp(whisper-cli)를 재사용하고 기본 모델은 ggml-small.bin으로 한다. 벤치마크에서는 large-v3-turbo도 비교한다. WhisperKit은 SpeechRecognizer 프로토콜 뒤에 둘 후속 옵션이다. 마이크 → 16kHz mono WAV를 앱 임시 폴더에 쓰고, 전사가 끝나면 즉시 삭제한다.
  • ADR-2 LLM: llama.cpp 공식 macOS arm64 릴리스(llama-server, 수십 MB)와 Qwen3-1.7B Instruct Q4KM GGUF(약 1.1~1.3GB)를 jarvis-launcher/.local-models/에 받고 .gitignore에 넣는다. 다운로드는 M3 시작 직전에 정확한 URL·용량·SHA256을 보고하고 진행한다. 앱이 관리하는 서브프로세스로 띄우며 127.0.0.1, 실행마다 무작위 포트와 무작위 API 키를 쓴다. 첫 요청 때 로드하고 유휴 시 종료한다. EXAONE은 NC 라이선스 때문에 비교 실험에만 쓰고 배포에는 넣지 않는다.
  • ADR-3 빌드·서명: SwiftPM으로 빌드하고 scripts/build-app.sh가 build/JARVISLauncher.app을 조립한다(Info.plist: LSUIElement, NSMicrophoneUsageDescription). ad-hoc 서명(codesign -s -)으로 로컬에서 실행하며 공증은 하지 않는다. 재빌드하면 마이크 권한을 다시 물을 수 있는데, 이는 알려진 한계로 기록한다.
  • ADR-4 새 프로젝트 기동: agent launch 대신 terminal create --command "claude --permission-mode plan --session-id <UUID> -n <slug>"로 TUI를 보장한다. JARVIS가 만든 세션은 UUID를 알기 때문에 재연결 키로 쓸 수 있다.
  • ADR-5 데이터 위치: 설정·매핑·체크포인트는 JSON 파일로 저장한다(UserDefaults는 쓰지 않는다). 기본 위치는 ~/Library/Application Support/<bundle-id>/이고, 개발·테스트 중에는 JARVIS_DATA_DIR=<프로젝트>/.local-data로 덮어써 폴더 밖 쓰기를 피한다. 마이크 TCC 항목만은 OS가 기록하는 것이라 피할 수 없다. 로그인 시 실행(SMAppService)은 구현만 하고, 작가님 승인 없이 켜지 않는다.

세션 매칭 키는 executionHostId + realpath(worktreePath) + worktreeId + agentIdentity이고, JARVIS가 만든 세션이면 claudeSessionId를 더한다. handle과 incarnationId는 런타임 값으로만 취급한다.

전송 직전 재검증(SendGuard)은 terminal show로 다음을 모두 확인한다. handle이 존재할 것, 확인 화면에 띄운 incarnationId와 worktreePath(realpath)·executionHostId == local이 같을 것, agentIdentity == claude, connected && writable && !orphaned. 그다음 terminal read --screen으로 권한 대화상자·질문 대기 화면이 아닌지 검사한다. 이 검사는 휴리스틱이어서 확실하지 않으면 차단한다. 하나라도 실패하면 전송 0회. 전송은 send --text --enter --wait-submit 5 --json 한 번이며, receipt를 전송 확인 / 상태 불명 / 실패로 매핑한다. 자동 재시도는 하지 않는다. 수동 재시도는 같은 --retry-request ID로만 허용한다.

7. 위험·알려진 한계(초기)

  • Claude 세션 ID를 Orca가 노출하지 않는다. 기존 세션에서 같은 경로에 Claude가 둘이면 매번 수동으로 선택해야 한다.
  • 입력 가능 상태(권한 대화상자·질문 대기)는 화면 텍스트 휴리스틱으로 판정한다. Claude Code UI가 바뀌면 깨질 수 있으므로, 판정이 애매하면 차단 쪽을 기본으로 한다.
  • ad-hoc 서명이라 재빌드하면 마이크 권한을 다시 물을 수 있다.
  • 원격 호스트(멕미니, ssh)는 MVP 전송 대상에서 제외한다(목록에는 미확인/원격으로 표시).
  • 테스트용 Orca 폴더 등록을 해제할 수단이 없을 수 있다(M0b에서 확인).

8. 검증 (End-to-end)

  1. swift build && swift test: 순수 로직·fake CLI 테스트 전부 통과(로그는 qa/evidence/unit/)
  2. scripts/build-app.sh && open build/JARVISLauncher.app(run-dev.sh로 JARVIS_DATA_DIR 지정)
  3. 실기 시나리오 A: 샌드박스 테스트 프로젝트 터미널을 페어링 → 핫키 → 입력 → 추천 → 확인 → 전송 확인 → orca terminal read --screen으로 도착 확인
  4. 실기 시나리오 B: 샌드박스 부모 폴더 → 새 프로젝트 → 플랜 모드 화면 증거 → 메타 프롬프트 1회 도착
  5. 실기 시나리오 C: 스킬 선택 → 테스트 터미널에 호출 문자열 1회
  6. AC 결과표(qa/evidence/README.md): AC별 PASS / FAIL / 미수행 + 근거 경로. 실패와 미검증은 그대로 적는다
