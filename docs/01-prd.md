# JARVIS Launcher — macOS 상주 프롬프트 런처 PRD

- **문서 버전:** 1.0
- **작성일:** 2026-10-27
- **상태:** 구현을 위한 초안 확정 제안 / 환경 의존 사항은 확인 필요
- **대상:** macOS / Apple Silicon M1 Pro, 통합 메모리 32GB / 개인 사용자 1인
- **구현 담당:** Claude Code (최초 작업은 Plan Mode)
- **제품 원칙:** JARVIS는 개발 에이전트가 아니라 사용자 의도를 정리하고 Orca에서 실행 중인 Claude Code 세션으로 *안전하게 전달하는 로컬 라우터*이다.
- **표기 규칙:** `[결정]`은 PRD에서 채택한 제품·구현 선택, `[확인 필요]`는 로컬 환경 또는 실측으로 검증할 사실, `[목표]`는 검증 전 성능 기준. 모델 품질·처리속도·메모리 목표는 측정 완료를 뜻하지 않는다.

## 1) 개요와 문제 정의

### 1.1 배경

사용자는 MacBook에서 Orca 터미널을 통해 여러 Claude Code 세션을 병행한다. 새 지시를 내리려면 해당 프로젝트의 Orca 탭을 찾고 터미널에 긴 요청을 입력해야 한다. 음성으로 생각을 빠르게 기록하고 프로젝트에 연결하는 과정이 단절되어 있다.

### 1.2 문제

- 여러 터미널 중 적절한 대상 세션을 사람이 매번 찾아야 한다.
- 생각난 요구를 실행 가능한 지시문으로 정리하는 데 반복적인 입력이 필요하다.
- 새 프로젝트 폴더 생성 → Orca 연결 → Claude Code 플랜 모드 실행 과정이 수동이다.
- 터미널 핸들이 앱 재시작·재부팅 뒤 달라지면 기존 연결을 신뢰하기 어렵다.
- 사용자가 의도하지 않은 세션으로 보내는 오발송은 단순 입력 불편보다 큰 위험이다.

### 1.3 제품 목표와 성공 조건

**핵심 경험:** 전역 핫키 → 가운데 반투명 입력창 → 타이핑 또는 한국어 받아쓰기 → 작업 유형·대상 추천 → 사용자가 확인·수정 → Orca에 전달.

**북극성 지표(목표):** 창을 호출한 이후 기존 프로젝트에 짧은 지시를 정확히 전달하는 과정을 *창 하나에서* 끝낸다. 자동 전송하지 않는다.

**성공 조건:** 기능이 많기보다 입력이 빠르고, 추천 근거가 이해 가능하고, 잘못된 터미널로 보낼 가능성이 구조적으로 통제된다.

### 1.4 명시적 경계

- **오프라인·무료 로컬 처리**는 음성 인식·세션 추천·프롬프트 정리에 적용된다. **Claude Code 자체는 기존 계정·네트워크·사용량 조건을 따르며 오프라인 실행 또는 무과금을 보장하지 않는다.**
- Orca와 Claude Code의 실행 결과는 JARVIS의 작업 완료와 다르다. MVP는 전송 확인까지만 보장하며 코드 구현 완료 판정은 하지 않는다.
- 실제 사용자 컴퓨터에 Orca, Claude Code, Whisper 중 일부가 설치되어 있다는 것은 brief의 전제이지 여기서 원격으로 확인한 사실이 아니다.

## 2) 사용자와 사용 시나리오

### 2.1 사용자 페르소나와 전제

- 개발 경험이 풍부한 개인 사용자 1명. 사용 OS는 macOS, 작업기기는 Apple M1 Pro/32GB.
- Orca에 여러 프로젝트/워크트리/터미널이 열린다. 일부는 Claude Code를 실행 중이지 않을 수 있다.
- 짧은 구어체와 음성 명령을 선호하며, 결과 지시문을 확인하고 수정할 통제권을 원한다.
- 기본 상위 프로젝트 폴더를 한 번 설정한다.

### 2.2 시나리오 A: 기존 프로젝트 요청

1. 사용자가 전역 핫키를 누른다.
2. 패널에 `지난번에 만들던 대시보드, 매출 그래프의 날짜 필터 고쳐줘`라고 입력하거나 받아쓰기한다.
3. 앱은 Orca 터미널 목록/프로젝트 메타데이터를 조회하고 로컬 판단 모델로 후보를 제시한다.
4. **추천 프로젝트·경로·해당 터미널**을 표시한다. 후보가 여럿이면 선택하게 한다.
5. 사용자가 원문과 전달할 지시문을 확인·수정한다.
6. 전송 직전 대상 터미널 핸들·작업 폴더·Claude Code 실행 상태를 다시 검증한다.
7. 앱은 확인된 터미널에 1회 전송하고 `터미널에 전달됨`을 표시한다. 실제 Claude 응답/작업 종료는 단정하지 않는다.

**예외:** 대상 없음, 동일 폴더의 Claude 세션 여러 개, Orca 꺼짐, Claude가 권한 승인/질문 대기 중, 전송 타임아웃, 재시작으로 핸들 무효 → 전송 금지 및 재선택/재시도.

### 2.3 시나리오 B: 새 프로젝트 시작

1. `새로운 독서 메모 앱을 만들어보자. 노션처럼 태그 검색이 필요해`라고 입력한다.
2. 앱이 작업을 `새 프로젝트`로 분류한다. 사용자가 분류를 수정할 수 있다.
3. 로컬 LLM이 원문을 보존하면서 목표, 기능 초안, 제약, 미결 질문, 첫 단계 산출물을 포함한 **메타 프롬프트**를 만든다.
4. 앱이 기본 상위 폴더 안의 프로젝트 슬러그(예: `reading-notes`)를 제안한다. 사용자는 이름과 최종 경로 및 프롬프트를 수정·확인한다.
5. 앱은 상위 경로·중복·심볼릭 링크·쓰기 권한을 검사하고 새 폴더를 **명시적 승인 후** 생성한다.
6. Orca에서 해당 폴더를 열거나 필요한 저장소 등록 절차를 밟고 **새 터미널(구조화된 채팅 UI가 아닌 터미널)**을 만든다.
7. Claude Code를 **플랜 모드**로 시작하고 실행 상태가 확인된 후 메타 프롬프트를 1회 전달한다.
8. 생성한 폴더와 터미널 연결을 로컬에 기록한다.

**예외:** CLI가 임의 폴더를 작업 공간으로 열지 못함, Git 저장소 필요, 폴더 중복/권한 부족, 모델 오류, Claude 실행 불가 → 안전하게 중단, 원문 유지, 후속 단계 재시도. 임의로 기존 폴더를 덮어쓰거나 `git init`하지 않는다.

### 2.4 시나리오 C: 스킬 호출

1. 사용자는 `스킬` 탭/모드에서 개인·프로젝트 스킬을 조회한다.
2. 현재 선택된 프로젝트에서 **사용 가능하다고 검증된** 스킬만 호출 대상으로 활성화한다.
3. 사용자가 스킬과 선택적인 인자를 확인한다. 예: `/review` 또는 `/my-plugin:review` 같은 *표시 예시*이며 실제 호출명은 환경에서 읽는다.
4. 호출 전 대상 세션을 재검증한 후 확인 버튼으로 해당 터미널에 스킬 호출 텍스트를 보낸다.
5. 스킬 이름 충돌, 세션별 사용 불가, `disable-model-invocation` 등의 설정 차이는 감지 가능한 범위만 반영하고 모호하면 사용자에게 안내한다.

**예외:** 로컬 파일에는 있으나 세션의 `/skills` 목록과 다름, 플러그인·계정 동기화 스킬은 파일 스캔에서 누락 → `추가 확인 필요`로 표시하고 맹목적 전송 금지.

## 3) 기능 요구사항

우선순위 P0 = MVP 필수, P1 = MVP 뒤 보강, P2 = 이후 버전.

### FR-01. 앱 상주·전역 핫키 (P0)

- **입력:** 기본 핫키 `Control + Option + Space` **[결정: 초기값, 충돌 시 변경]**, 메뉴바 클릭.
- **출력:** 현재 포인터가 위치한 화면 중앙에 Spotlight 느낌의 반투명 패널. 패널이 열리면 입력창에 키보드 포커스.
- **행동:** 패널이 닫혀 있으면 열고, 열려 있으면 숨긴다. Esc는 기록을 보존하고 패널만 닫는다(녹음 중이면 녹음 중단). 여러 데스크톱/전체화면에서 표시 가능하도록 테스트한다.
- **예외:** 핫키 선점/등록 실패 → 메뉴바에서 재설정 및 충돌 안내. macOS 권한이 없더라도 가능한 핫키 등록 경로를 우선 사용한다.

### FR-02. 텍스트 입력 (P0)

- **입력:** 한국어/영어/혼합 텍스트, 붙여넣기, 문장 내 경로·명령·기호.
- **출력:** 편집 가능한 원문 입력창, 입력 내용 미리보기.
- **규칙:** 개행 지원. Enter는 줄바꿈 또는 추천 진입으로 오동작하지 않도록 `⌘ + Enter = 다음 단계`로 통일. 자동 전송 금지. 공백만 있는 입력은 진행 불가.
- **예외:** 너무 긴 입력(권장 8,000자 초과) → 잘라내지 말고 경고 및 편집 요청; 모델 제한은 별도 확인.

### FR-03. 로컬 음성 받아쓰기 (P0)

- **입력:** 버튼 클릭 → 마이크 녹음 → 다시 클릭하여 종료(누르고 말하기는 MVP 제외).
- **출력:** 전사 결과가 편집 가능한 텍스트로 입력; 기존 텍스트가 있으면 커서에 삽입.
- **규칙:** 마이크 권한은 실제 녹음 요청 때 획득. 모델 선택/다운로드는 초기 설정에서 사용자가 승인. 기본 언어 `ko`, 영어 개발 용어 혼용 수용. 음성 데이터는 로컬 처리하며 기본 저장 금지.
- **예외:** 권한 거부, 오디오 장치 없음, 모델 미설치/로드 실패, 녹음 빈 내용, 잡음, 녹음 중 패널 닫힘 → 오류 표시·텍스트 입력 계속 가능. `보낸 뒤 자동 지우기` 이외 자동 삭제 정책은 설정에서 정한다.

### FR-04. Orca 탐색과 최초 페어링 (P0)

- **입력:** 설치된 `orca` CLI, 현재 실행 중인 Orca, 사용자가 지정한 프로젝트 폴더.
- **출력:** 터미널 후보 목록(표시명, 로컬 절대 프로젝트 경로, repo/worktree 구분, 호스트, Claude Code 상태, 마지막 확인 시각, 연결 상태).
- **규칙:** 구조화 출력(JSON)을 파싱하고 미확인 필드는 비워 둔다. 사용자 설정에서 세션을 프로젝트에 연결·해제할 수 있다. 터미널 제목만으로 동일성 판단 금지.
- **예외:** `orca` 없음, 버전 불일치, JSON 불완전, 여러 호스트, Claude가 아닌 일반 셸, 터미널의 작업 디렉터리 식별 불가 → `미확인` 상태로 표시하고 전송 차단.

### FR-05. 앱 시작·재시작 시 자동 재연결 (P0)

- **입력:** 로컬에 저장한 프로젝트 매핑 + 새 Orca CLI 조회 결과.
- **출력:** `연결됨` / `사용자 확인 필요` / `오프라인` / `미확인`.
- **규칙:** `정규화 절대경로(realpath)` + `실행 호스트 ID` + `repo/worktree 식별자` + 가능한 경우 `Claude 세션 식별자`를 매칭 키로 사용한다. **런타임 핸들은 저장해도 임시값 취급**한다. 동일 경로에 후보가 2개 이상이면 자동 선택 금지. 재연결은 사용자 전송을 유발하지 않는다.
- **예외:** 폴더 이동/이름 변경, 중복 worktree, 호스트 미확인, Orca 재시작, 사라진 터미널 → 기존 연결을 보류·재확인. 재부팅 후 세션이 실제 복원되지 않았다면 `복원 실패/실행 안 됨`을 정확히 표시한다.

### FR-06. 요청 유형 분류·세션 추천 (P0)

- **입력:** 사용자 원문 + **최소 메타데이터**(프로젝트 별칭·경로의 마지막 구성요소·사용자가 저장한 설명·세션 상태), 필요 시 최근 상태의 요약(민감정보 제외).
- **출력:** `existing_project | new_project | skill | unknown`, 추천 대상 상위 후보, 이유 한 줄, 불확실성 플래그.
- **규칙:** LLM은 후보 중 하나만 ID로 반환하며 임의의 터미널을 만들어내지 못한다. 경로 별칭/명시적 프로젝트명 규칙 매칭을 먼저 적용하고 모호한 경우 LLM으로 추천. `confidence` 숫자는 보정 전 신뢰도처럼 사용하지 않는다. 모호하면 수동 선택을 기본값으로 한다.
- **예외:** 모델 무응답·JSON 파싱 실패·목록 변경·대상 미존재 → 수동 선택 UI로 폴백. 추천만으로 자동 전송 금지.

### FR-07. 메타 프롬프트 생성·원문 보호 (P0)

- **입력:** 자유 발화, 선택적 사용자 추가 지시(예: 기술 스택, 대상 폴더).
- **출력:** 편집 가능한 다음 구조의 Markdown 프롬프트: `사용자 원문`, `목적`, `범위`, `완료 기준(초안)`, `제약/금지`, `확인할 질문`, `첫 작업(계획만 작성)`. 새 프로젝트에서는 프로젝트 이름 1~3개 제안.
- **규칙:** 원문을 별도로 보존. 모르는 사실은 추측하지 않고 `미정`으로 표시. 중요한 부정문·경로·고유명사·버전·명령은 임의로 변경하지 않는다. 모델 반환값은 사용자 지시가 아닌 **검토 대상 데이터**로 취급한다.
- **예외:** 의미 왜곡, 출력 형식 오류, LLM 부재 → 기본 템플릿으로 정리하거나 원문 그대로 전송. 모든 경우 사용자 편집 가능.

### FR-08. 전송 확인·단일 전달 (P0)

- **입력:** 사용자 승인한 텍스트, 대상 프로젝트, 현재 핸들.
- **출력:** `전송 준비` → `전송 시도` → `전송 확인` / `상태 불명` / `실패`.
- **규칙:** 확인 화면에 **최종 문자열, 프로젝트명, 경로, 호스트, 터미널**을 보여준다. 보내기 직전에 CLI로 터미널/작업 폴더/상태를 재검사한다. 프로젝트당 직렬 전송. 전송 중 버튼 중복 입력 방지. 중복 실행 위험이 있으므로 **타임아웃 뒤 자동 재전송 금지**.
- **예외:** 로그인/권한 대기, TUI에 셸 프롬프트가 떠 있음, 전송 도중 터미널 종료, 응답 누락 → `전송 여부 불명` 표시 후 화면 조회·수동 재시도. **CLI 성공 응답과 Claude가 프롬프트 처리한 것은 구별한다.**

### FR-09. 새 프로젝트 생성·Claude 플랜 모드 실행 (P0, CLI 실증 게이트)

- **입력:** 사용자가 승인한 새 폴더명, 기본 상위 폴더, 메타 프롬프트.
- **출력:** 신규 폴더, Orca 작업 공간과 **새 터미널**, 플랜 모드 Claude 세션, 초기 요청 전달 상태.
- **규칙:** 파일 생성 전 realpath 상위폴더 내부임을 재검사, `..`·절대경로 주입·심볼릭 링크 우회·이름 충돌 차단. 필요 시 Git 초기화/Orca repo 등록은 **UI에서 별도 명시적 승인**을 받아 처리한다. Claude 실행 명령·플래그는 설치된 버전의 `claude --help`로 최종 확인. 시작 후 터미널 화면/상태를 점검해 플랜 모드 진입 성공을 확인하고 나서 프롬프트를 전송. Orca가 새 폴더를 CLI로 열거나 해당 폴더에 터미널을 생성할 수 없는 경우 무리한 UI 자동화는 하지 않고 명시적 안내 + 수동 폴더 열기 대체 경로를 제공한다.
- **예외:** 폴더만 생성되고 Orca 작업이 실패하면 기존 폴더를 자동 삭제하지 않음. 단계별 진행 상태와 `여기서 이어하기` 표시. 단계를 재실행해도 폴더/터미널 중복 생성 방지.

### FR-10. Claude Code 스킬 조회·선택·호출 (P0)

- **입력:** 개인·프로젝트 스킬 디렉터리, 레거시 명령 디렉터리, 해당 세션에서 실행한 `/skills` 결과(확인 가능 범위).
- **출력:** 스킬 이름, 출처(개인/프로젝트/플러그인/계정 동기화/레거시/내장), 설명, 프로젝트 적용 여부, 호출 문자열, `검증됨/추정/불명`.
- **규칙:** 우선 `~/.claude/skills/<name>/SKILL.md` 및 프로젝트의 `.claude/skills/<name>/SKILL.md`를 읽어 후보 생성. 레거시 `.claude/commands/*.md` 지원. 플러그인·계정 동기화·내장 스킬은 폴더 스캔만으로 전부 알 수 없으므로 **대상 Claude 세션의 `/skills`가 실제 가용 목록의 기준**이다. `/skills` 결과 파싱이 불안정하면 사용자가 수동 확인 후 호출할 수 있도록 표시. 충돌하는 이름은 정식 호출명 확인 전 비활성화.
- **예외:** 잘못된 YAML frontmatter, 링크/권한 거부, 중복 이름, 목록 갱신 지연, `/skills` 명령 실행이 기존 작업 흐름을 방해할 가능성 → 읽기 전용/수동 갱신 우선, 잘못된 자동 호출 금지.

### FR-11. 설정 및 진단 (P0)

- **입력:** 핫키, 기본 프로젝트 상위 폴더, STT/LLM 모델 경로, 명시적 다운로드 승인, 로그인 시 실행, 세션 별칭/매핑.
- **출력:** 저장된 설정, CLI/마이크/모델/권한 상태, 연결 테스트 버튼과 상세 진단.
- **예외:** 경로 없음, 모델 체크섬 불일치, 바이너리 손상, 선택 핫키 충돌, 미승인 폴더 접근 → 해당 기능만 비활성화하고 앱은 정상 유지.

### FR-12. 상태 알림 (P0 한정)

- 메뉴바 아이콘/패널에서 `연결 끊김`, `음성 변환 중`, `준비`, `전송 확인`, `재확인 필요` 표시.
- 기존 Claude Code의 실제 답변·완료·질문 추적 및 푸시 알림은 P1로 보류한다. 필요 시 `Orca에서 열기` 또는 `터미널 화면 다시 읽기`만 제공.

## 4) 화면과 흐름

### 4.1 디자인 원칙

- 작은 집중형 유틸리티, Dock 아이콘 없이 메뉴바 상주(최초 설치 중 설정 창은 별도 표시 가능).
- 반투명 둥근 패널 + 가벼운 그림자 + 단색 강조. 광범위한 에이전트 대시보드를 만들지 않는다.
- **접근성을 위해** macOS 투명도 감소/다크 모드/고대비 설정을 반영한다.
- 화면 중앙 위치는 현재 포인터가 위치한 디스플레이의 `visibleFrame` 기준(화면 상단 메뉴바와 Dock 피함).

## 5) 기술 설계

### 5.1 플랫폼/프로세스 구성

- **언어/UI:** Swift, SwiftUI, 필요 부분 AppKit.
- **배포:** 우선 개인용 서명 macOS 앱, Apple Silicon 우선. Mac App Store 배포는 MVP 제외(외부 CLI 실행·프로젝트 폴더 접근을 허용하는 샌드박스 정책 문제는 별도 검토).
- **최소 지원 OS:** macOS 14 이상 **[결정: 목표]**, 실제 Xcode/SDK/WhisperKit 호환은 구현 시 확인.
- **메뉴바:** `MenuBarExtra` 또는 필요 시 `NSStatusItem`.
- **패널:** `NSPanel` + `NSHostingView`로 SwiftUI 내용 렌더링; 투명/블러 배경은 `NSVisualEffectView`, 입력이 가능한 key-window 동작과 비활성 패널 플래그를 실기기 검증.
- **전역 핫키:** 시스템 전역 단축키 API(Carbon `RegisterEventHotKey` 등)로 구현 가능 여부 확인, 사용자 설정과 충돌 검출. **핫키만으로 Accessibility 권한을 요구하지 않도록** 설계.
- **마이크:** `AVAudioEngine`/`AVAudioSession` 계열 중 macOS 호환 방식 확인, `NSMicrophoneUsageDescription` 포함, 시스템 TCC 권한 상태 반영.
- **접근성:** Orca CLI가 충분하면 불필요. UI 스크립트/키보드 이벤트 주입 fallback이 실제 필요할 때만 `AXIsProcessTrustedWithOptions`를 통해 명시적 승인 받고 그 외에는 요청하지 않는다.
- **시스템 권한:** 사용자 홈 전체 디스크 권한/화면 기록/관리자 권한을 기본 요구하지 않는다. 필요가 생기면 사용자에게 사유를 설명하고 최소 권한으로 제한.
- **로그인 자동 실행:** 선택 설정으로 제공; `SMAppService` 적용 가능성 확인.

### 5.2 아키텍처와 모듈

```text
SwiftUI PromptPanel / SettingsView / MenuBar
                    |
                AppCoordinator
        +-----------+-------------+
        |           |             |
     Input      LocalBrain      SessionRegistry
        |           |             |
  Microphone    IntentRouter      OrcaAdapter
  STTAdapter    PromptComposer    CLIProcessRunner
        |           |             |
        +-----------+-------------+
                    |
          DispatchCoordinator
          (revalidate + approve
           + serialize + record)
                    |
              Orca CLI → Orca Terminal → Claude Code

       PreferencesStore / ModelManager / Diagnostics
```

**개발 규칙:** `OrcaAdapter`, `SpeechRecognizer`, `LocalLLM`, `SkillCatalog`를 프로토콜로 추상화해 테스트에서 fake 구현을 주입한다. UI에서 CLI를 직접 호출하지 않는다. 모든 프로세스/모델 호출은 비동기 처리, 취소 및 타임아웃 지원.

### 5.3 권장 로컬 STT 모델 비교

| 후보 | 한국어 | 속도·크기·통합 관점 | 판정 |
|---|---|---|---|
| **Whisper multilingual small + WhisperKit/Core ML** | 공식 multilingual 모델이므로 한국어 대상 가능. 한국어 개발 용어 인식률 **실측 확인 필요** | Swift 네이티브 통합 우수. `small` 모델 자체 약 466MiB는 **whisper.cpp 가중치 기준**이며 WhisperKit Core ML 패키지 크기는 별도 확인. M1 Pro 전사 지연은 실측 필요 | **MVP 기본** |
| **Qwen3-ASR-0.6B** | 공식 지원 언어에 한국어 포함 | 0.6B 파라미터. 오프라인/스트리밍 지원 발표. Apple Silicon용 직접 Swift 통합·패키지 크기·지연은 확인 필요. Python/MLX 브리지 가능성 PoC 필요 | 한국어 품질 대안 실험 |
| **SenseVoiceSmall (234M)** | 공식 지원 언어에 한국어 포함 | 비교적 작은 파라미터 수, 고속 지향. macOS Apple Silicon 지원/Swift 브리지와 모델 파일 크기는 확인 필요. 발표 벤치마크의 속도를 M1 Pro 수치로 전용 불가 | 경량 대안 실험 |

**기본 선택 [결정]:** `WhisperKit + multilingual small`을 먼저 구현한다. 현재 설치된 `Whisper`의 실행 형태(`whisper`, `whisper.cpp`, Python 패키지, 모델 파일)를 조사해 *호환될 때만* 재사용한다. 이미 설치되어 있다고 해서 WhisperKit용 Core ML 모델이 있다고 가정하지 않는다. WhisperKit 배포 정책·SPM 최신 API는 실제 고정 버전에서 검증.

**승급 기준:** 동일한 개인 음성 테스트셋(일반 한국어 10문장 + 한국어/영어 개발 용어 10문장 + 경로·명령 10문장 + 잡음 환경 10문장, 총 40개 **[목표 설계]**)에 대해 CER/용어정확도, 실시간률(RTF), 녹음 종료 후 P50/P95 지연, 디스크 사용량/상주 메모리를 측정한다. Qwen3-ASR가 현저히 개선되고 통합 비용·지연을 만족할 때 기본 모델 변경을 별도 결정한다. 공개 비교 수치나 우열은 **확인 필요**.

**STT 실행:** 마이크 PCM 캡처 → 음성 감지/전처리(VAD, 선택) → 로컬 전사 → 텍스트 입력에 삽입. 음성 파일은 기본 저장 금지, 임시 파일을 써야 한다면 Application Support의 전용 임시 위치 사용·즉시 삭제. 최초 모델 다운로드만 사용자 동의 후 네트워크 사용.

### 5.4 권장 로컬 경량 LLM 비교

| 후보 | 한국어 및 지시 처리 | 모델 규모/배포 | 판정 |
|---|---|---|---|
| **Qwen3-1.7B Instruct 계열** | 다국어·구조화 지시 적합 여부 실측 필요 | 1.7B, Apache-2.0. GGUF `Q4_K_M` 공개 양자화 파일 약 **1.28GB(제공 파일에 따라 차이)**. llama.cpp/Metal 활용 가능 | **MVP 기본** |
| **EXAONE 4.0 1.2B** | 한국어·영어 지원, 한국어 특화 대안 | 1.2B급, 온디바이스 지향. **EXAONE AI Model License Agreement 1.2-NC** 사용 조건 확인 필수, GGUF/실행 엔진 호환 확인 필요 | 한국어 비교 후보 |
| **Gemma 3 4B IT** | 140개 이상 언어 지원(4B), 구조화 응답 후보 | 4B로 상대적으로 무거움. Gemma 이용 약관·양자화 파일·실측 메모리 확인 필요 | 품질 비교/후순위 |

**기본 선택 [결정]:** Qwen3-1.7B Q4_K_M, JSON 스키마 검증 기반. 한국어 성능이 목적에 부족하면 EXAONE 1.2B를 비교하되 비상업 라이선스 조건에 저촉되는 배포·활용은 하지 않는다. 모델 학습 벤치마크 점수를 JARVIS 세션 추천 정확도로 오인하지 않는다.

**실행 방식 [결정]:** `llama.cpp` 계열의 앱 관리형 *로컬 서브프로세스*로 모델을 구동한다. macOS Metal 백엔드 사용. 앱이 관리하는 loopback(`127.0.0.1`) 서버 형태를 우선 PoC하되 **고정 포트 외부 노출 금지, 포트 충돌·다른 로컬 프로세스 접근 방지, 인증 수단과 실행 파일 서명·배포 방식 확인 필요**. 보안 요건을 만족하지 못하면 인프로세스 네이티브 라이브러리 브리지로 대체한다. 모델은 첫 요청 시 lazy load, 유휴 시 unload 가능하게 한다. `llama.cpp` 실행 바이너리·실제 API는 버전 고정 후 확정. OpenAI/Anthropic 등의 외부 LLM API는 호출하지 않는다.

**LLM 입력:** 원문 + **선별된** 프로젝트 메타정보(전체 소스코드/터미널 출력 기본 미전송) + JSON 출력 스키마. LLM은 결정을 제안할 뿐 명령 실행·파일 작성·터미널 선택 권한이 없다.

**출력 예시 — 앱 내부 프로토콜(외부 CLI 옵션이 아님):**

```json
{
  "intent": "existing_project",
  "suggested_project_id": "local-project-uuid",
  "candidate_ids": ["local-project-uuid"],
  "reason": "사용자가 매출 필터를 언급했고 프로젝트 별칭과 일치함",
  "needs_user_selection": false,
  "draft_prompt": "매출 필터 동작을 점검하고 수정 계획을 먼저 제시해 주세요.",
  "unknowns": []
}
```

- `project_id`가 제공한 후보 목록에 없거나 JSON 파싱에 실패하면 버리고 수동 선택으로 폴백.
- `needs_user_selection`은 모호성 판단을 위한 플래그이며 자동 발송 승인으로 사용하지 않는다.
- 원문은 별도 필드로 유지하고 사용자가 UI에서 승인한 최종 텍스트만 전송한다.

### 5.5 Orca CLI 연동: 반드시 현장 검증

공식 Orca 문서는 CLI를 통해 워크트리/터미널 조회, 화면·스트림 읽기, 텍스트 전송, 터미널 생성, 에이전트 실행을 소개한다. *사용자 로컬 설치 버전의 실제 명령·옵션·JSON 스키마는 여기서 확정하지 않는다.*

**구현 시 `orca --help`로 확인.** 이어서 설치 버전의 관련 하위 도움말과 테스트 출력을 확인하고 `docs/orca-cli-contract.md`에 **검증된 명령, 옵션, 출력 필드, 실패 코드, 지원 버전**을 기록한다. 예시 문서의 명령을 검증 없이 코드에 하드코딩하지 않는다.

우선 확인할 계약:

1. 실행 중인 Orca 상태 조회, 현 Mac의 호스트 식별.
2. 전체 repo/worktree 및 관련 터미널 목록 조회(복수 worktree/호스트 포함, JSON 범위 확인).
3. 터미널 작업 디렉터리와 Claude Code 실행 여부·세션 식별 정보의 확보 가능성.
4. 현재 터미널 화면/출력 읽기와 사용자가 입력 가능한 idle/prompt 상태의 구별.
5. 지정한 **명시적 핸들**로 텍스트를 한 번 보낸 결과의 의미(수락/전달/반영 여부).
6. 특정 폴더 기반 Orca 등록/열기, 새 터미널 생성, 작업 디렉터리 설정.
7. 새 터미널에서 **Claude Code TUI**를 Plan Mode로 직접 시작할 수 있는지(Orca native structured chat로 바뀌지 않는지).
8. 앱 재시작 전후 runtime-scoped 핸들 유효성, 타임아웃/오류 시 재조회 정책.

CLI 호출은 `Process`로 **실행 파일 URL + 인자 배열**을 전달한다. 셸 문자열 이어 붙이기나 `sh -c` 원문 보간 금지. 명령별 실행시간 제한, 표준출력 JSON 크기 제한, 종료 코드 체크, stderr 원문 비밀정보 마스킹. UI에 raw CLI 출력을 기본 노출하지 않는다.

**절대 규칙:** 사용자 승인, 대상 식별, CLI 재검증 세 조건 중 하나라도 실패하면 전송하지 않는다. Orca CLI가 없는 경우 Accessibility/UI 자동화를 조용히 대신 쓰지 않는다.

### 5.6 페어링·세션 복구 설계

**데이터 모델(내부, 개략):**

```text
ProjectRecord {
  id: UUID
  alias: String
  canonicalLocalPath: URL
  repoIdentity?: String
  worktreeIdentity?: String
  hostIdentity?: String
  lastVerifiedClaudeSessionIdentity?: String
  lastSeenAt?: Date
}
TerminalCandidate {
  runtimeHandle: String     // 재시작 뒤 신뢰 금지
  canonicalPath?: URL
  hostIdentity?: String
  repoIdentity?: String
  worktreeIdentity?: String
  agentKind?: String        // claude / other / unknown
  agentSessionIdentity?: String
  runtimeState?: String
}
Binding { projectID, terminalFingerprint, lastRuntimeHandle?, verificationState }
```

**자동 재연결 알고리즘:**

1. 앱 시작 → CLI 런타임 확인 및 전체 관련 세션 후보 조회.
2. 보존된 프로젝트마다 `host + canonical path + repo/worktree`가 같은 후보를 필터링.
3. 가능하면 `agent=Claude Code`와 기존 세션 ID까지 대조.
4. 정확히 하나이고 현재 실행·입력 상태를 검증 가능하면 `연결됨`. 둘 이상/정보 누락은 `확인 필요`.
5. 유효한 후보가 없으면 `오프라인`. Orca/호스트 조회 범위가 부분적이면 `미확인`으로 구별.
6. **전송 직전 항상 해당 터미널을 재조회**하고 프로젝트 경로·호스트 불일치 시 취소.
7. 사용자가 수동으로 선택한 페어링은 영구 핸들이 아니라 프로젝트 정체성·선택 기준으로 저장한다.

**별도 위험:** 같은 프로젝트 폴더에 서로 다른 Claude 세션이 2개라면 폴더 경로만으로 세션 동일성을 보장할 수 없다. **세션 식별자를 CLI가 제공하지 않는다면 자동 재연결 금지하고 매번 후보를 확인**한다. Orca가 재부팅 후 터미널 자체를 복원하지 않은 경우 신규 세션을 몰래 만들지 않는다.

### 5.7 새 프로젝트 실행 파이프라인

```text
[원문 입력]
   ↓
[로컬 LLM: 메타 프롬프트 + 폴더명 제안]
   ↓
[사용자: 프로젝트 경로/최종 프롬프트 승인]
   ↓
[폴더 안전성 검사 + 폴더 생성]
   ↓
[Orca에 경로 등록/열기: CLI 지원 여부 검증]
   ↓
[필요 시 Git 초기화/저장소 등록: 별도 승인]
   ↓
[새 Orca 터미널 생성: 해당 경로 검증]
   ↓
[Claude Code를 Plan Mode로 실행: `claude --help`로 옵션 확인]
   ↓
[실제 Plan Mode/입력 가능 상태 확인]
   ↓
[사용자가 확인한 메타 프롬프트 1회 전송]
   ↓
[프로젝트 매핑 저장 + '터미널에 전달됨']
```

**Plan Mode 유의:** 단순히 `계획부터 세워줘`라고 프롬프트에 적는 것과 Claude Code의 실제 **Plan Mode 권한 상태**는 다르다. 플래그가 설치 버전에 존재하는지 `claude --help`로 확인하고, 화면/프로세스 상태로 검증 가능한 방식 확보가 필수다. 정식 Plan Mode 상태를 확인할 수 없다면 전송을 중단해 사용자가 확인하도록 한다.

**오류 복구:** 생성 작업의 `operationId`와 `createdFolderPath`, `orcaWorkspaceIdentity`, `terminalHandle`, `promptDelivered`를 단계별 기록한다(민감 원문 저장은 선택). 각 단계가 성공한 경우 재실행 시 재사용, 중복 생성 금지. `promptDelivered`를 판정할 수 없다면 자동 재전송 금지.

### 5.8 스킬 카탈로그/호출 구현

1. **발견 단계:** 사용자 홈과 프로젝트의 `.claude/skills` 하위 `SKILL.md`, 예전 `.claude/commands` Markdown 파일에서 메타데이터 파싱. 스캔 범위를 해당 프로젝트와 공식 경로로 제한.
2. **확장 발견:** 플러그인 스킬, 계정 동기화 스킬, 내장 스킬은 일반 파일 스캔으로 완전하게 확보할 수 없다. 현재 세션의 `/skills` 또는 해당 Claude Code 버전에서 제공하는 공식 목록 메커니즘을 확인한다. CLI가 목록 구조화 출력을 제공하지 않는다면 **목록 비교 기능은 제한**한다.
3. **정규화:** `source`, `displayName`, `effectiveInvocationName`, `description`, `availability`, `projectScope`, `lastVerifiedAt`.
4. **실행:** 사용자가 최종 호출 문자열·대상 세션을 보고 승인한 뒤 기존 Orca `send` 전달 경로를 재사용. 인자·파일 경로는 사용자가 편집 가능.
5. **안전:** 스킬 파일 본문의 지시를 JARVIS가 실행하지 않는다. 스킬 목록 파싱은 메타데이터 읽기일 뿐이다. 호출 시의 실제 수행은 Claude Code 권한 체계에 맡긴다.

### 5.9 로컬 데이터·보안 설계

- `UserDefaults`: 핫키, UI 옵션, 마지막 선택 프로젝트 등 소량의 설정.
- `Application Support/<bundle-id>/`: 프로젝트 매핑(JSON 또는 SQLite), 모델/캐시 경로 참조, 작업 단계 체크포인트.
- **기본 보관 정책:** 음성 원본 저장 안 함; 프롬프트 원문·터미널 화면 출력·LLM 처리 입력은 영구 저장하지 않음. 앱 재시작 후 임시 원문 복구는 MVP 제외(사용자 승인한 새 프로젝트 생성 중 체크포인트에 원문이 필요하면 암호화/보존기간 설계 후에만 허용).
- **폴더 접근:** 설정 시 NSOpenPanel로 선택, 필요한 곳만 접근. 보안 범위 북마크가 필요한 배포 모드에서는 별도 확인.
- **로컬 프로세스 보호:** 승인된 앱 번들 내부 LLM 런타임만 실행, 임의 플러그인 바이너리 실행 금지. loopback 서버를 쓴다면 비인가 앱 접근·포트 노출 시험.
- **프롬프트 인젝션:** 터미널 화면·스킬 설명·프로젝트 이름은 모두 비신뢰 데이터로 취급. LLM에 전달한 문자열이 JARVIS의 전송 규칙/보안 규칙을 변경할 수 없다.

**Claude Code 플랜 모드 첫 작업 지시:** 이 PRD를 읽고 **바로 구현하지 말 것**. 먼저 `/docs/orca-cli-contract.md`에 실제 명령의 `--help` 결과, 세션 동일성 판단에 필요한 필드, 새 프로젝트 기동의 실증 가능 여부와 차선 경로를 정리한다. 이어 기술 스택·패키지 버전, 테스트 전략, 작업 순서, 미결 사항과 구현 단위를 포함하는 계획을 작성하고 사용자 승인 후 코드 변경을 시작한다. 실제 환경을 확인하지 못하는 부분은 가짜 명령으로 대체하지 말고 `[확인 필요]`로 남긴다.

## 6) 비기능 요구사항

### 6.1 속도와 응답성(모두 **측정 전 목표**)

| 항목 | 제안 목표 | 측정 방식 |
|---|---|---|
| 핫키 → 패널 포커스 | 워밍 상태 P95 ≤ 250ms | M1 Pro 30회 반복, 활동 모니터 부하 병행 |
| 앱 시작 → 메뉴바 준비 | P95 ≤ 2초, 모델은 지연 로드 | 10회 실행 |
| 10초 한국어 발화 → 전사 종료 | 녹음 중단 뒤 P95 ≤ 5초 **[실측 후 조정]** | 40문장 셋, RTF도 기록 |
| 짧은 입력 분류 + 구조화 | 모델 warm P95 ≤ 8초 **[실측 후 조정]** | 100개 발화 벤치마크 |
| CLI 세션 목록 조회 | 로컬 정상 연결 P95 ≤ 3초 **[실측 후 조정]** | 터미널 1/5/10개 |
| 전송 | CLI 응답 P95 ≤ 3초 **[실측 후 조정]** | 성공/실패/타임아웃 분리 |

**UI 스레드 정지 허용 안 함.** 모델 cold-start가 오래 걸리면 진행 상태와 취소 제공. 임계값은 외부 사실이 아니라 제품 합격 목표이며 측정 결과를 기록해 필요 시 조정한다.

### 6.2 메모리·CPU·저장 공간

- **[목표]** 모델 미로드·유휴 상태 추가 메모리 ≤ 250MB. 실제 가능성은 Instruments로 확인.
- **[목표]** STT+LLM 동시 사용을 포함한 앱 및 하위 로컬 추론 프로세스 합계 추가 메모리 ≤ 5GB. 모델별 메모리 실측과 다른 앱/Claude 세션과의 간섭 평가 필수.
- 사용 안 하는 모델 unload, 다운로드 모델 별 디스크 크기를 설치 전 명시, 모델 데이터 삭제 UI 제공.
- 유휴 시 오디오 지속 캡처/백그라운드 CPU 폴링 금지; Orca 상태 새로고침은 이벤트 + 사용자가 시작한 조회를 우선.

### 6.3 개인정보·네트워크

- STT와 판단 엔진은 로컬 오프라인 처리. 모델 다운로드 전만 명시적 네트워크 승인 필요.
- 사용자가 입력한 명령에는 프로젝트 정보가 있을 수 있으므로 텔레메트리·클라우드 로그·제3자 API 전송하지 않음.
- Claude Code로 승인 전송한 뒤의 데이터 흐름은 Claude Code 설정·계정 정책에 따름. JARVIS가 이를 막거나 오프라인으로 바꾸지 않는다.
- 모델 프로세스도 의도치 않은 네트워크를 사용하지 않는지 검증.

### 6.4 권한·복원력

- 마이크 권한은 필요 시에만. 접근성 권한은 원칙적으로 불필요하며 UI 자동화 대안 채택 시에만 사용.
- 화면 녹화/전체 디스크 접근/관리자 권한을 포괄 요구하지 않는다.
- Orca 종료·CLI 오류·STT/LLM 모델 실패에도 앱/사용자 입력이 살아 있어야 한다.
- 장애 상태는 `실패`, `상태 불명`, `대상 없음`을 구분하여 사용자 재시도 판단을 돕는다.

### 6.5 품질과 진단

- Swift 순수 로직 유닛 테스트 + CLI fake 테스트 + 실제 Orca E2E 3종 + 재시작 시나리오.
- 릴리스 전에 macOS 다중 모니터, 전체화면, 한영 전환, 다크 모드, 권한 거부를 수동 점검.
- 최소 권한·민감정보 마스킹된 진단만 기록. 사용자가 `진단 정보 내보내기`를 눌러도 민감정보 포함 가능성을 미리 경고.

## 7) MVP 범위와 제외 범위

### 7.1 MVP(P0)

- 메뉴바 상주, 전역 핫키, 반투명 패널, 직접 텍스트 입력.
- 로컬 한국어 STT와 편집 가능한 전사 결과.
- Orca CLI 탐색, 프로젝트↔실행 터미널 페어링, 재시작 후 안전한 재매칭.
- 기존 프로젝트 세션 추천(수동 선택 포함), 편집·확인 후 1회 전송.
- 새 프로젝트 이름/폴더/메타 프롬프트 확인, 폴더 생성, 새 Orca 터미널 + Claude Plan Mode 시작, 프롬프트 전달. **단, Spike 0에서 Orca 폴더 등록 기능이 불가능하면 이 기능을 조용히 생략하지 말고 수동 등록 fallback을 명시적으로 제공한 후 MVP 완료 판정에 한계를 보고한다.**
- 설치된 Claude 스킬 발견·목록·선택·호출(세션별 가용성 확인 범위까지).
- 모델·권한·기본 프로젝트 경로·핫키·세션 연결 설정.

### 7.2 명시적 제외(P1/P2)

- 웨이크 워드 및 상시 음성 대기.
- Windows/Linux용 앱, iOS/Android 원격 컨트롤.
- 외부 LLM/STT 클라우드 API 연결.
- 완전 자동 세션 전송, 사용자 승인 없는 폴더/터미널 생성.
- Claude Code 최종 응답의 통합 채팅 UI, 작업 완료 추적·질문 알림·푸시(P1).
- 멀티에이전트 오케스트레이션·자율 작업 분배·삭제/배포 자동 승인.
- 영구 프롬프트 검색/벡터 메모리/사용자 행동 학습(P2).
- 사용자가 설치하지 않은 스킬 자동 설치 또는 플러그인 관리.
- Mac App Store 출시/자동 업데이트.

### 7.3 MVP 수용을 위한 사전 실증 게이트

**G0 Orca 환경 계약:** 전체 세션 조회, 지정 터미널에 안전 전송, 폴더에 연결된 신규 터미널 생성 경로, 호스트/프로젝트 식별 최소 필드 확보. **[확인 필요]**

**G1 Claude 계약:** 실제 Plan Mode 플래그와 진입 확인 방법, 스킬 목록의 신뢰 가능한 확인 방법. **[확인 필요]**

**G2 모델 계약:** Apple M1 Pro에서 모델 설치·추론 성공, 오프라인 동작 확인, 주요 한국어 용어 테스트. **[확인 필요]**

G0/G1 중 안전 전송/플랜 모드 확인이 불가능하면 임의 가정으로 대체하지 말고 구현 계획에서 blocker로 제기한다.

## 8) 수용 기준(Acceptance Criteria)

아래 항목은 **테스트 가능한 목표**이며 아직 합격을 의미하지 않는다.

1. **AC-01 핫키 호출:** 메뉴바 앱 실행 후 기본/사용자 지정 전역 핫키를 30회 반복 시 패널이 정상 표시되고 입력 포커스가 위치하며 두 번째 호출로 닫힌다. 충돌은 오류로 안내한다.
2. **AC-02 창 위치:** 내장·외부 모니터 각각에서 실행할 때 포인터가 있는 화면의 사용 가능 영역 안에 패널이 전부 표시된다. 다크 모드·고대비에서도 입력할 수 있다.
3. **AC-03 입력 보존:** 한국어/영어 혼합·경로·여러 줄 텍스트를 입력하고 분류/뒤로 가기를 반복해도 원문이 임의 변형·삭제되지 않는다. 입력이 비어 있으면 진행 버튼 비활성화.
4. **AC-04 마이크 권한:** 처음 녹음 버튼 사용 시 필요한 권한을 요청한다. 허용하면 녹음하고 거부하면 안내 후 텍스트 입력을 계속할 수 있다.
5. **AC-05 받아쓰기:** M1 Pro에서 사전 준비한 한국어 40개 발화를 전사해 편집 가능한 입력창에 표시한다. CER·RTF·P95을 측정해 `docs/model-benchmarks.md`에 기록한다. 임의로 `한국어 최고 인식률`을 주장하지 않는다.
6. **AC-06 오프라인 추론:** 모델이 설치된 상태에서 외부 인터넷을 차단해도 STT/LLM 분류·구조화는 동작한다. 다운로드 필요 시 사용자 승인 이전에 모델을 자동 다운로드하지 않는다.
7. **AC-07 Orca 목록:** 실제 Orca에서 복수 프로젝트/터미널 5개를 생성해 앱이 목록을 읽고 각 후보의 검증 가능한 경로·호스트·상태를 표시한다. 식별 불가 후보는 `미확인`으로 표시한다.
8. **AC-08 페어링:** 프로젝트 A/B에 각각 서로 다른 Claude 터미널이 존재할 때 수동 연결을 저장하고 앱만 재시작해도 동일 프로젝트에 다시 매칭된다(핸들 재조회).
9. **AC-09 재부팅/런타임 핸들 변경:** Orca를 재시작하거나 핸들이 바뀐 테스트 픽스처를 주입했을 때 저장한 구 핸들로 전송하지 않고 새 후보를 검증한다. 대상이 복원되지 않으면 오프라인 처리한다.
10. **AC-10 중복 세션 안전:** 같은 폴더의 Claude 터미널 2개를 만들거나 호스트/작업경로 정보를 제거한 가짜 CLI 응답을 넣으면 앱이 자동 대상 확정과 전송을 차단하고 수동 확인을 요구한다.
11. **AC-11 추천 검증:** 별칭·키워드로 명백한 요청 20개와 모호한 요청 20개를 입력해 상위 후보/이유를 보이고, 모호한 요청은 사용자가 대상을 고르지 않으면 전송하지 않는다. 추천 정확도를 별도 기록한다(합격률 수치 미정, 확인 필요).
12. **AC-12 프롬프트 검토:** 분류 모델이 만든 내용은 항상 편집 가능하고 `사용자 원문`, 부정 조건, 경로, 숫자를 보존한다. 의도적으로 잘못된 JSON 출력 시 수동 템플릿으로 폴백한다.
13. **AC-13 오발송 방지:** 사용자 확인 직후 대상 터미널이 다른 폴더/호스트로 바뀌도록 조작한 테스트에서 실제 전송 횟수가 **0회**이다.
14. **AC-14 정확한 1회 전송:** 검증된 Claude Code 터미널에 확인된 한 개의 프롬프트를 보내고 CLI 결과를 `터미널에 전달됨`으로 표시한다. 지연 시 자동 재전송하지 않으며 중복 클릭은 1회만 처리한다.
15. **AC-15 전송 불명 처리:** `send` 뒤 응답이 타임아웃되는 가짜 CLI를 사용하면 `상태 불명`이 표시되고 자동 재전송이 일어나지 않는다.
16. **AC-16 신규 폴더:** 기본 상위 폴더 아래의 사용자가 승인한 이름만 생성한다. 이미 존재하는 폴더, 상위 경로 탈출(`../`), symlink 우회, 권한 없음에 대해 기존 파일을 덮어쓰지 않고 중단한다.
17. **AC-17 신규 Claude Plan Mode:** 신규 폴더에서 새 Orca 터미널이 열리고 Claude Code TUI가 **실제 Plan Mode** 상태임을 검증한 뒤 승인한 메타 프롬프트 1회를 전달한다. 실패하면 어떤 단계에서 멈췄는지 표시한다.
18. **AC-18 생성 중단·이어하기:** 폴더 생성 이후 Orca 실행에 실패하게 만든 뒤 재시도하면 기존 폴더를 재사용하고 중복 터미널·중복 프롬프트 전송이 발생하지 않는다.
19. **AC-19 스킬 조회:** 개인 스킬, 프로젝트 스킬, 레거시 명령 각 하나씩을 테스트 경로에 만들면 이름·출처를 표시한다. 플러그인·내장 등 미확인 출처는 전체 목록이라고 주장하지 않는다.
20. **AC-20 스킬 호출:** 현재 Claude 세션에서 사용할 수 있는 스킬을 하나 선택하고 호출 문자열·대상을 확인한 뒤 정확히 한 번 전송한다. 이름 충돌/가용성 미확인 시 차단한다.
21. **AC-21 권한 최소화:** Orca CLI만으로 기능이 가능한 환경에서는 앱이 접근성·화면 녹화·전체 디스크 접근을 무조건 요청하지 않는다. 마이크 권한 거부 시 앱을 사용할 수 있다.
22. **AC-22 개인정보:** 음성 녹음·프롬프트 원문이 기본 설정에서 영구 저장되지 않음을 확인하고, 제3자 API 호출 없이 로컬 모델이 동작함을 네트워크 로그로 확인한다.
23. **AC-23 모델 실패 복원력:** STT 또는 LLM 파일을 임시 제거한 상황에서도 패널·직접 입력·수동 대상 선택·전송은 가능하다(필요 CLI 정상이라는 조건).
24. **AC-24 성능 측정:** 6.1/6.2 목표를 Apple M1 Pro/32GB에서 실제 측정해 릴리스 체크리스트에 P50/P95, 앱/하위 프로세스 메모리, OS/모델 버전을 기록한다. 미달 항목은 공개적으로 미달로 표시한다.
25. **AC-25 기능 회귀:** 앱 재시작, Orca 재시작, Claude 종료, 비활성 터미널, 다중 모니터, 한영 입력, macOS 절전/복귀를 포함한 수동 E2E 테스트 결과가 문서화된다.
